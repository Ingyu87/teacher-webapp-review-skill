# 5 API 키와 환경 변수의 노출 점검

분류: 공통 보안 점검

사용하는 경우: 외부 API나 배포 환경 변수를 사용하는 경우

준비할 정보: 서비스 이름, 키의 용도, 변수 이름, 저장소 공개 범위

### 어디서 확인하나요

연습은 #/keys에서 F12 → Sources(소스) 내부 클릭 → Ctrl+P → lab-exposed.js → apiKey를 봅니다. 찾은 연습용 값은 웹앱의 확인란에 입력합니다. 실제 키의 폐기·사용 내역은 해당 서비스 관리 화면에서 확인합니다.

### 구현할 때 적용할 조건

- 비밀키를 서버 전용 설정에서만 읽고 브라우저는 필요한 결과만 받게 해 줘.

- 서버에 옮긴 호출에도 로그인·권한·입력 검사와 호출 제한이 필요한지 확인해 줘.

- 이미 노출된 키는 내가 발급 서비스에서 폐기·재발급하고 사용 내역을 확인할 순서를 알려 줘. 자동으로 키를 폐기하지 마.

- 예시 환경 파일에는 변수 이름과 설명만 넣고, 저장소 이력 삭제나 강제 푸시는 별도 승인 없이 하지 마.

### 1 현재 상태부터 확인하기

사용할 때: 프로젝트를 연 뒤 처음 보냅니다. 파일을 고치기 전 단계입니다.

```text
활동: API 키와 환경 변수의 노출 점검
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 서비스 이름, 키의 용도, 변수 이름, 저장소 공개 범위
현재 상황: [입력]
사용할 가상 자료: [입력]

이 활동에 해당하는지부터 확인해 줘. 아직 파일이나 설정은 수정하지 마.
1. 키를 읽는 파일과 사용 위치를 찾고 공개용 설정값과 비밀키를 구분해 줘. 실제 값은 출력하지 마.
2. 브라우저 번들, HTML, Network 응답, 오류 기록, 저장소 현재 파일과 과거 기록의 노출 가능성을 각각 확인해 줘.
3. .env와 .gitignore 설정을 확인하고 이미 추적 중인 파일을 제외 목록에 적기만 한 경우를 찾아 줘.
4. 클라이언트 공개 접두사가 붙은 환경 변수와 서버 전용 변수를 현재 프레임워크 기준으로 설명해 줘.

결과는 표로 정리해 줘. 표에는 확인 항목, 현재 동작, 근거가 있는 파일이나 설정 위치, 발견한 문제와 추가로 확인할 내용을 적어 줘. 코드에서 확인한 사실과 추정은 구분해 줘. 내가 직접 확인할 메뉴·버튼·파일 이름도 알려 줘. 파일을 읽지 못했다면 그 사실을 표시해 줘.
실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
참고할 확인 위치: 연습은 #/keys에서 F12 → Sources(소스) 내부 클릭 → Ctrl+P → lab-exposed.js → apiKey를 봅니다. 찾은 연습용 값은 웹앱의 확인란에 입력합니다. 실제 키의 폐기·사용 내역은 해당 서비스 관리 화면에서 확인합니다.
```

다음 행동: 현재 구조와 해당 여부를 확인합니다. 모르는 정보는 먼저 확인하고, 수정이 필요하면 2번으로 진행합니다.

### 2 수정 방법과 범위 정하기

사용할 때: 1번 답변에서 실제로 고칠 항목을 골랐을 때 보냅니다.

```text
활동: API 키와 환경 변수의 노출 점검

준비 정보: 서비스 이름, 키의 용도, 변수 이름, 저장소 공개 범위
현재 상황: [입력]
사용할 가상 자료: [입력]

이번에 고칠 항목: [입력]

구현 전에 다음 조건으로 수정 계획을 만들어 줘.

기존 기능을 유지하면서 문제를 고칠 방법부터 제안해 줘. 방법이 여러 가지라면 필요한 서비스와 비용, 사용 방법이 달라지는 부분, 이전 상태로 되돌릴 방법을 비교해 줘. 반드시 고쳐야 할 부분과 선택해서 개선할 부분을 구분해 줘.
변경할 파일, 학생 또는 교사 화면에서 달라질 부분, 필요한 관리 설정, 시험할 가상 입력을 순서대로 적어 줘. 서버가 없는 앱이라면 지금 할 수 있는 것과 서버가 필요한 것을 분리해 줘.
아직 코드를 수정하거나 서비스를 만들지 마. 내가 결정해야 할 사항이 있으면 선택지와 차이를 설명하고 물어봐 줘.
```

다음 행동: 수정할 내용과 비용, 정보 수집·전송·보관 방식이 달라지는지 확인한 뒤 진행할 방법을 정합니다. 학교가 판단해야 하는 내용은 먼저 확인합니다.

### 4 수정 결과 직접 확인하기

사용할 때: 구현이 끝났거나 기존 기능이 안전하게 동작하는지 검증할 때 보냅니다.

```text
활동: API 키와 환경 변수의 노출 점검
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 서비스 이름, 키의 용도, 변수 이름, 저장소 공개 범위
현재 상황: [입력]
사용할 가상 자료: [입력]
이번 수정 내용: [입력 또는 기존 기능 검증]
시험할 버전과 주소: [입력]

다음 조건을 가상 자료로 다시 시험해 줘.
1. 새 빌드의 Sources와 Network에서 비밀키가 전달되지 않는지 값 노출 없이 확인해 줘.
2. 서버 기능은 정상 동작하고 키가 없는 환경에서는 비밀값 없는 오류를 보여 주는지 시험해 줘.
3. 기존 키 폐기 여부는 제공사에서 확인한 결과만 적고 추측하지 마.
4. 공개용 Firebase 설정 등은 키처럼 보인다는 이유만으로 삭제하지 말고 실제 권한 규칙을 함께 확인해 줘.

내가 직접 따라 할 수 있도록 준비 계정과 상태 → 클릭 또는 입력 → 확인할 실제 탭·요청·필드 → 기대 결과를 항목마다 적어 줘.
확인할 위치: 연습은 #/keys에서 F12 → Sources(소스) 내부 클릭 → Ctrl+P → lab-exposed.js → apiKey를 봅니다. 찾은 연습용 값은 웹앱의 확인란에 입력합니다. 실제 키의 폐기·사용 내역은 해당 서비스 관리 화면에서 확인합니다.
자기 앱에서 이름이 다르면 코드와 실제 요청에서 맞는 이름을 찾아 줘. 실제로 존재하는지 확인하지 않은 요청명을 만들어 내지 마.
허용해야 할 동작과 차단해야 할 동작을 함께 시험해 줘. 항목마다 실행 여부, 실제 결과, 확인한 화면이나 기록을 적고, 시험하지 못했다면 이유를 설명해 줘. 응답 코드와 실제로 받은 자료를 함께 확인하고, 저장 기능이 있다면 저장된 결과도 확인해 줘.
이 활동을 완료해도 앱 전체의 안전이 보장된다고 표현하지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

다음 행동: 기대 결과와 실제 결과가 같으면 활동 기록을 정리합니다. 다르면 “오류 해결” 프롬프트를 사용하고 같은 조건으로 재시험합니다.

```text
사용할 가상 자료: [입력]
현재 겪는 상황: 정적 웹앱만 있고 서버가 없을 때
이미 한 행동과 나온 결과: [입력]

비밀키가 필요한 기능을 브라우저에 넣지 않는 구조를 제안해 줘. 서버 함수 추가, 기능 제외 등 대안을 비용과 함께 비교하고 내가 고르기 전 새 서비스를 연결하지 마.
먼저 관련 코드·화면·설정에서 현재 상태를 확인하고 이 상황이 생긴 이유를 근거와 함께 설명해 줘. 현재 환경에서 확인할 수 없는 것은 따로 표시해 줘.
이 활동에서 유지할 조건:
1. 비밀키를 서버 전용 설정에서만 읽고 브라우저는 필요한 결과만 받게 해 줘.
2. 서버에 옮긴 호출에도 로그인·권한·입력 검사와 호출 제한이 필요한지 확인해 줘.
3. 이미 노출된 키는 내가 발급 서비스에서 폐기·재발급하고 사용 내역을 확인할 순서를 알려 줘. 자동으로 키를 폐기하지 마.

진행 순서를 “지금 확인할 것 → 선택 가능한 방법 → 내가 승인할 변경 → 실행 후 다시 확인할 결과”로 정리해 줘. 앱에 필요 없는 기능을 추가하거나 검사를 끄는 방식으로 해결하지 마.
재시험에서는 다음 조건을 포함해 줘:
1. 새 빌드의 Sources와 Network에서 비밀키가 전달되지 않는지 값 노출 없이 확인해 줘.
2. 서버 기능은 정상 동작하고 키가 없는 환경에서는 비밀값 없는 오류를 보여 주는지 시험해 줘.
수정이 필요하면 먼저 범위를 제안하고 내 확인 전 운영 설정을 바꾸지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

사용할 때: F12에 설명한 파일·요청이 없거나 확인할 곳을 모르겠을 때 보냅니다.

### 예상과 다른 결과가 나올 때

