# 40 더 이상 쓰지 않는 웹앱 완전 종료

분류: 사용 종료와 서비스 정리

사용하는 경우: 재개 계획 없이 해당 웹앱의 운영과 불필요한 자원을 정리하려는 경우

준비할 정보: 종료할 정확한 프로젝트와 주소, 종료일, 이용자 안내, 보관할 자료와 기간, 자원 목록, 삭제·키 폐기·구독 해지별 승인 범위

### 어디서 확인하나요

각 서비스의 프로젝트 설정·데이터 관리·키 관리·구독 및 청구 화면에서 확인합니다. 정확한 팀·프로젝트·자원 이름과 공식 문서를 먼저 대조합니다. F12로는 접속 요청의 결과만 확인할 수 있으며 DB·백업 삭제, 키 폐기, 구독 해지는 해당 관리 화면의 근거가 필요합니다.

### 구현할 때 적용할 조건

- 이용자 안내와 신규 요청 차단부터 계획해 줘. 진행 중 작업 처리와 필요한 자료 내보내기를 마친 뒤 삭제를 검토해 줘.

- 백업 파일의 존재만 확인하지 말고 안전한 위치에서 열거나 복원 가능한지 확인할 방법을 제시해 줘. 백업에 담긴 개인정보의 권한과 정리 시점도 정해 줘.

- 정확한 자원별로 삭제·키 폐기·구독 해지 대상을 나눠 영향과 복구 가능성을 설명하고 각각 명시적으로 승인받아 줘. 공유 자원과 미확인 자원은 제외해 줘.

- 승인한 자원만 순서대로 정리하고 매 단계 결과를 확인해 줘. 예상 밖의 실패나 다른 앱 영향이 발견되면 반복 삭제나 다른 자원 정리로 넘어가지 말고 멈춰 줘.

### 1 대상과 연결 서비스 확인

사용할 때: 중단·종료 전에 읽기 전용으로 조사할 때 사용합니다.

```text
활동: 더 이상 쓰지 않는 웹앱 완전 종료
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 종료할 정확한 프로젝트와 주소, 종료일, 이용자 안내, 보관할 자료와 기간, 자원 목록, 삭제·키 폐기·구독 해지별 승인 범위
현재 상황: [입력]
사용할 가상 자료: [입력]

실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
문서 속 예시는 실행 승인이 아닙니다. 대상과 영향을 확인한 뒤 이번 요청에 명시적으로 승인한 작업만 실행해 줘. 보안 조치의 필수 여부와 내가 선택한 운영 종료 작업을 구분해 줘.

1. 완전 종료가 맞는지와 대상 프로젝트를 확인해 줘. 배포·서버·DB·파일·백업·AI 키·예약 작업·도메인·구독의 전용 여부와 다른 앱 사용처를 읽기 전용으로 확인해 줘.
2. 남길 코드와 필요한 기록, 삭제할 개인정보, 백업의 보관 기간·접근 권한을 구분해 줘. 목적과 보관 기준이 불명확한 자료는 임의로 삭제하지 마.
3. 공식 문서에서 자원별 삭제·해지 영향, 복구 가능 여부, 비용 정산 시점과 보관료를 확인해 줘. 확인하지 못한 항목은 미확인으로 적어 줘.
4. 학생 접속, 포털·공유 링크, 자동 배포, 외부 자동 요청과 예약 실행이 다시 서비스를 이용하거나 되살릴 수 있는지 확인해 줘.

아직 설정·자료·키·구독을 변경하지 마. 확인 사실과 미확인 항목을 나누고 실제 관리 위치를 알려 줘.
```

다음 행동: 대상과 전용·공유 여부를 확인한 뒤 계획을 검토합니다.

### 4 실제 중단·종료 결과 확인

```text
2. 관리 화면에서 승인한 자원 삭제·키 폐기·구독 해지 상태를 각각 확인하고 확인 시각과 근거를 기록해 줘. 키를 노출하거나 유료 호출로 폐기를 시험하지 마.
```

### 보관할 자료나 백업이 확실하지 않은 경우

사용할 때: 기본 순서로 진행하다가 이 상황에 해당하면 사용합니다.

```text
활동: 더 이상 쓰지 않는 웹앱 완전 종료
앱 이름과 프로젝트: [입력]

현재 상황: [입력]
사용할 가상 자료: [입력]
현재 겪는 상황: 보관할 자료나 백업이 확실하지 않은 경우
이미 한 행동과 나온 결과: [입력]

삭제를 보류하고 자료 종류·보관 목적·기간·담당자를 정리해 줘. 내보내기와 복원 확인 계획을 제시하고 실제 학생 자료를 공개 저장소나 대화에 올리지 마.
먼저 관련 코드·화면·설정에서 현재 상태를 확인하고 이 상황이 생긴 이유를 근거와 함께 설명해 줘. 현재 환경에서 확인할 수 없는 것은 따로 표시해 줘.
이 활동에서 유지할 조건:
1. 이용자 안내와 신규 요청 차단부터 계획해 줘. 진행 중 작업 처리와 필요한 자료 내보내기를 마친 뒤 삭제를 검토해 줘.
2. 백업 파일의 존재만 확인하지 말고 안전한 위치에서 열거나 복원 가능한지 확인할 방법을 제시해 줘. 백업에 담긴 개인정보의 권한과 정리 시점도 정해 줘.
```
