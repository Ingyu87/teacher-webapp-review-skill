# 26 실제 운영에 맞는 이용약관 초안 작성

분류: 학교 제출 자료

사용하는 경우: 앱 이용 조건을 안내할 문서가 필요한 경우

준비할 정보: 운영 주체, 대상, 기능, 계정 방식, 비용, 문의 방법, 종료 정책

### 어디서 확인하나요

기존 앱의 푸터 이용약관과 실제 화면을 비교합니다. aiworld의 사례는 형식을 참고하되 운영 주체·처리 방식은 자신의 앱에 맞춰 작성합니다.

### 구현할 때 적용할 조건

- 목적·이용 대상·제공 기능·이용 시 주의사항·이용 제한과 문의·서비스 변경 및 종료를 실제 운영 방식에 맞춰 초안으로 작성해 줘.

- 모르는 운영 정보는 그럴듯한 문구로 채우지 말고 확인할 질문으로 분리해 줘.

- 학생에게 일방적 책임을 떠넘기거나 모든 권리를 포기시키는 문구를 만들지 마.

- 법적 적합성이 확정된 문서라고 표현하지 말고 학교가 검토할 초안과 확인 항목을 함께 제공해 줘.

### 체험과 참고 링크

- [관련 사례 또는 공식 자료 1](https://aiworld-ig.vercel.app/login.html)

### 1 현재 상태부터 확인하기

사용할 때: 프로젝트를 연 뒤 처음 보냅니다. 파일을 고치기 전 단계입니다.

```text
활동: 실제 운영에 맞는 이용약관 초안 작성
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 운영 주체, 대상, 기능, 계정 방식, 비용, 문의 방법, 종료 정책
현재 상황: [입력]
사용할 가상 자료: [입력]

이 활동에 해당하는지부터 확인해 줘. 아직 파일이나 설정은 수정하지 마.
1. 앱에서 실제로 제공하는 기능과 운영자가 실제로 할 수 있는 지원 범위를 정리해 줘.
2. 기존 약관에서 다른 서비스 이름·유료 결제·광고 등 우리 앱에 없는 내용을 찾아 줘.
3. 학생이 작성한 자료의 이용 범위와 계정 제한·종료 절차를 확인해 줘.
4. 개인정보처리방침에 써야 할 내용을 약관의 포괄 동의로 대신하고 있는지 확인해 줘.

결과는 표로 정리해 줘. 표에는 확인 항목, 현재 동작, 근거가 있는 파일이나 설정 위치, 발견한 문제와 추가로 확인할 내용을 적어 줘. 코드에서 확인한 사실과 추정은 구분해 줘. 내가 직접 확인할 메뉴·버튼·파일 이름도 알려 줘. 파일을 읽지 못했다면 그 사실을 표시해 줘.
실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
참고할 확인 위치: 기존 앱의 푸터 이용약관과 실제 화면을 비교합니다. aiworld의 사례는 형식을 참고하되 운영 주체·처리 방식은 자신의 앱에 맞춰 작성합니다.
```

다음 행동: 현재 구조와 해당 여부를 확인합니다. 모르는 정보는 먼저 확인하고, 수정이 필요하면 2번으로 진행합니다.

```text

변경할 파일, 학생 또는 교사 화면에서 달라질 부분, 필요한 관리 설정, 시험할 가상 입력을 순서대로 적어 줘. 서버가 없는 앱이라면 지금 할 수 있는 것과 서버가 필요한 것을 분리해 줘.
아직 코드를 수정하거나 서비스를 만들지 마. 내가 결정해야 할 사항이 있으면 선택지와 차이를 설명하고 물어봐 줘.
```

다음 행동: 수정할 내용과 비용, 정보 수집·전송·보관 방식이 달라지는지 확인한 뒤 진행할 방법을 정합니다. 학교가 판단해야 하는 내용은 먼저 확인합니다.

### 3 선택한 범위 구현하기

사용할 때: 수정 계획을 검토한 뒤 승인할 범위를 직접 적고 보냅니다.

```text

수정할 파일 또는 기능 범위: [입력]

위에 승인한 범위만 구현해 줘. 시작 전에 현재 변경 파일을 확인해 다른 작업을 보존해 줘.

한 부분씩 수정하고 실행 결과를 확인해 줘. 기존 디자인과 정상 기능은 유지해 줘. 새 서비스 생성·운영 자료 삭제·유료 호출·커밋·푸시·배포는 이 요청에 구체적으로 승인한 경우에만 실행해 줘. 요청하지 않은 변경이 필요하면 진행 전에 이유를 설명해 줘.
수정 후 바꾼 파일과 이유, 실행한 검사, 아직 하지 못한 시험, 내가 누를 버튼 순서를 적어 줘. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

사용할 때: 구현이 끝났거나 기존 기능이 안전하게 동작하는지 검증할 때 보냅니다.

```text

다음 조건을 가상 자료로 다시 시험해 줘.
1. 조항별로 실제 화면·기능·운영 방침 근거를 연결해 줘.
2. 앱에 없는 기능이나 운영 주체가 들어가지 않았는지 확인해 줘.
3. 학생과 보호자가 이해할 수 있는 요약과 상세 문서가 서로 모순되지 않는지 확인해 줘.
4. 게시 전에 작성일·적용일·문의처의 실제 값을 사람이 확인할 목록으로 정리해 줘.

내가 직접 따라 할 수 있도록 준비 계정과 상태 → 클릭 또는 입력 → 확인할 실제 탭·요청·필드 → 기대 결과를 항목마다 적어 줘.
확인할 위치: 기존 앱의 푸터 이용약관과 실제 화면을 비교합니다. aiworld의 사례는 형식을 참고하되 운영 주체·처리 방식은 자신의 앱에 맞춰 작성합니다.
자기 앱에서 이름이 다르면 코드와 실제 요청에서 맞는 이름을 찾아 줘. 실제로 존재하는지 확인하지 않은 요청명을 만들어 내지 마.
허용해야 할 동작과 차단해야 할 동작을 함께 시험해 줘. 항목마다 실행 여부, 실제 결과, 확인한 화면이나 기록을 적고, 시험하지 못했다면 이유를 설명해 줘. 응답 코드와 실제로 받은 자료를 함께 확인하고, 저장 기능이 있다면 저장된 결과도 확인해 줘.
이 활동을 완료해도 앱 전체의 안전이 보장된다고 표현하지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

다음 행동: 기대 결과와 실제 결과가 같으면 활동 기록을 정리합니다. 다르면 “오류 해결” 프롬프트를 사용하고 같은 조건으로 재시험합니다.

### 다른 앱 약관을 복사한 경우

```text

각 조항이 우리 앱의 기능과 운영 방식에 맞는지 검토해 줘. 해당 없는 내용을 삭제할 때는 이유를 설명하고, 작성에 필요한 정보가 빠져 있으면 질문해 줘.
먼저 관련 코드·화면·설정에서 현재 상태를 확인하고 이 상황이 생긴 이유를 근거와 함께 설명해 줘. 현재 환경에서 확인할 수 없는 것은 따로 표시해 줘.
이 활동에서 유지할 조건:
1. 목적·이용 대상·제공 기능·이용 시 주의사항·이용 제한과 문의·서비스 변경 및 종료를 실제 운영 방식에 맞춰 초안으로 작성해 줘.

진행 순서를 “지금 확인할 것 → 선택 가능한 방법 → 내가 승인할 변경 → 실행 후 다시 확인할 결과”로 정리해 줘. 앱에 필요 없는 기능을 추가하거나 검사를 끄는 방식으로 해결하지 마.
재시험에서는 다음 조건을 포함해 줘:
1. 조항별로 실제 화면·기능·운영 방침 근거를 연결해 줘.
2. 앱에 없는 기능이나 운영 주체가 들어가지 않았는지 확인해 줘.
수정이 필요하면 먼저 범위를 제안하고 내 확인 전 운영 설정을 바꾸지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```
