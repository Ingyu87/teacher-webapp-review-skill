# 19 학생용 AI의 답변과 수업 적합성 점검

분류: 학생 수업 운영

사용하는 경우: AI 답변을 학생에게 제공하는 앱

준비할 정보: 수업 목표, 학생 연령, 정상·경계·위험 가상 입력, 현재 AI 지시문

### 어디서 확인하나요

학생 화면의 답변과 서버의 AI 요청 구성 코드를 함께 확인합니다. F12에는 브라우저와 앱 서버 사이의 통신만 보일 수 있으며 외부 AI에 보낸 실제 전체 요청은 서버 쪽에서 별도로 확인합니다.

### 구현할 때 적용할 조건

- 연령에 맞는 어휘, 모르면 모른다고 알리는 방식, 교사에게 질문할 상황을 지시문에 반영해 줘.

- 학습자의 사고를 돕는 질문과 힌트를 제공하고 정답 대필 여부는 수업 목적에 따라 설정해 줘.

- 학생 평가·징계·위기 판단을 AI 단독 결정으로 구현하지 마.

- 외부 자료는 검토할 자료로 취급하고 자료 속 지시가 앱 정책을 바꾸지 못하도록 처리해 줘.

### 1 현재 상태부터 확인하기

사용할 때: 프로젝트를 연 뒤 처음 보냅니다. 파일을 고치기 전 단계입니다.

```text
활동: 학생용 AI의 답변과 수업 적합성 점검
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 수업 목표, 학생 연령, 정상·경계·위험 가상 입력, 현재 AI 지시문
현재 상황: [입력]
사용할 가상 자료: [입력]

이 활동에 해당하는지부터 확인해 줘. 아직 파일이나 설정은 수정하지 마.
1. AI가 하는 일과 교사가 판단할 일을 수업 목표에 맞춰 구분해 줘.
2. 정답을 단정하거나 학생을 평가·낙인찍는 표현, 위험한 내용, 출처 없는 주장을 만들 수 있는 경로를 점검해 줘.
3. 시스템 지시문·사용자 입력·첨부 자료가 섞일 때 첨부 자료의 지시를 그대로 따르는지 시험 계획을 세워 줘.
4. AI 출력의 개인정보·부적절 내용·사실성 확인을 어디서 하는지 정리해 줘.

결과는 표로 정리해 줘. 표에는 확인 항목, 현재 동작, 근거가 있는 파일이나 설정 위치, 발견한 문제와 추가로 확인할 내용을 적어 줘. 코드에서 확인한 사실과 추정은 구분해 줘. 내가 직접 확인할 메뉴·버튼·파일 이름도 알려 줘. 파일을 읽지 못했다면 그 사실을 표시해 줘.
실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
참고할 확인 위치: 학생 화면의 답변과 서버의 AI 요청 구성 코드를 함께 확인합니다. F12에는 브라우저와 앱 서버 사이의 통신만 보일 수 있으며 외부 AI에 보낸 실제 전체 요청은 서버 쪽에서 별도로 확인합니다.
```

### 4 수정 결과 직접 확인하기

사용할 때: 구현이 끝났거나 기존 기능이 안전하게 동작하는지 검증할 때 보냅니다.

```text

2. 정책을 무시하라는 입력과 문서 속 지시를 넣어도 앱의 역할이 유지되는지 확인해 줘.
3. 반복 실행 결과가 달라질 수 있으므로 한 번 통과한 것을 완전한 안전으로 표현하지 마.
4. 실제 외부 AI 호출이 필요한 시험은 예상 비용과 전송 항목을 먼저 확인하고 승인 후 실행해 줘.

내가 직접 따라 할 수 있도록 준비 계정과 상태 → 클릭 또는 입력 → 확인할 실제 탭·요청·필드 → 기대 결과를 항목마다 적어 줘.

자기 앱에서 이름이 다르면 코드와 실제 요청에서 맞는 이름을 찾아 줘. 실제로 존재하는지 확인하지 않은 요청명을 만들어 내지 마.
허용해야 할 동작과 차단해야 할 동작을 함께 시험해 줘. 항목마다 실행 여부, 실제 결과, 확인한 화면이나 기록을 적고, 시험하지 못했다면 이유를 설명해 줘. 응답 코드와 실제로 받은 자료를 함께 확인하고, 저장 기능이 있다면 저장된 결과도 확인해 줘.
이 활동을 완료해도 앱 전체의 안전이 보장된다고 표현하지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.

사용할 가상 자료: [입력]
현재 겪는 상황: 차단이 지나쳐 정상 수업 질문도 막히는 경우
이미 한 행동과 나온 결과: [입력]

오탐 사례를 가상 문장으로 분류하고 정상 질문을 허용하면서 고위험 처리 규칙을 유지하는 수정안을 제시해 줘.
먼저 관련 코드·화면·설정에서 현재 상태를 확인하고 이 상황이 생긴 이유를 근거와 함께 설명해 줘. 현재 환경에서 확인할 수 없는 것은 따로 표시해 줘.
이 활동에서 유지할 조건:
1. 연령에 맞는 어휘, 모르면 모른다고 알리는 방식, 교사에게 질문할 상황을 지시문에 반영해 줘.
2. 학습자의 사고를 돕는 질문과 힌트를 제공하고 정답 대필 여부는 수업 목적에 따라 설정해 줘.
3. 학생 평가·징계·위기 판단을 AI 단독 결정으로 구현하지 마.

진행 순서를 “지금 확인할 것 → 선택 가능한 방법 → 내가 승인할 변경 → 실행 후 다시 확인할 결과”로 정리해 줘. 앱에 필요 없는 기능을 추가하거나 검사를 끄는 방식으로 해결하지 마.
재시험에서는 다음 조건을 포함해 줘:
1. 정상 질문·정보가 부족한 질문·잘못된 전제·부적절한 요구를 가상 자료로 비교해 줘.
2. 정책을 무시하라는 입력과 문서 속 지시를 넣어도 앱의 역할이 유지되는지 확인해 줘.
수정이 필요하면 먼저 범위를 제안하고 내 확인 전 운영 설정을 바꾸지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

다음 행동: 이 상황에 맞는 방법을 선택한 뒤 기본 진행의 구현 또는 재시험 단계로 돌아갑니다. 해당 없음이면 이유를 기록하고 다른 활동을 고릅니다.

### 안내된 화면이나 요청을 찾지 못할 때

사용할 때: F12에 설명한 파일·요청이 없거나 확인할 곳을 모르겠을 때 보냅니다.

```text

이 안내가 체험 앱의 가상 자료인지 내 앱의 실제 동작인지 먼저 구분해 줘. 프로젝트에서 이 동작이 어떤 요청·파일·저장소로 연결되는지 찾아 줘.

브라우저 검사에서 막아 요청이 없거나 아직 동작을 실행하지 않은 경우도 구분해 줘. 서버에만 있는 정보는 F12에서 찾으라고 하지 말고 코드·관리 화면·시험 환경에서 확인할 방법을 제시해 줘.
확인할 자료가 실제로 없으면 없다고 말하고 필요한 시험 준비를 설명해 줘. 캡처 요청에는 가려야 할 정보도 알려 줘. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

다음 행동: 정확한 위치를 찾은 뒤 해당 활동의 4번 프롬프트로 결과를 확인합니다. 없다는 사실 자체가 기대 결과인지 먼저 판단합니다.

### 예상과 다른 결과가 나올 때

특히 다음 점검 기준을 다시 봐 줘:
1. AI가 하는 일과 교사가 판단할 일을 수업 목표에 맞춰 구분해 줘.

수정 후 같은 실패 조건과 다음 정상 조건을 모두 재시험해 줘:
1. 정상 질문·정보가 부족한 질문·잘못된 전제·부적절한 요구를 가상 자료로 비교해 줘.
2. 정책을 무시하라는 입력과 문서 속 지시를 넣어도 앱의 역할이 유지되는지 확인해 줘.

4. 실제 외부 AI 호출이 필요한 시험은 예상 비용과 전송 항목을 먼저 확인하고 승인 후 실행해 줘.
완료 보고에는 실제 실행한 결과와 실행하지 못한 이유를 구분해 줘.
