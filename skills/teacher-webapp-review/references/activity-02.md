# 2 F12로 교사용 비밀번호 찾기

분류: 공통 보안 점검

사용하는 경우: 교사용 비밀번호나 화면 잠금 기능이 있는 경우

준비할 정보: 연습 앱 주소, 자기 앱의 교사 접속 방식, 가상 계정

### 어디서 확인하나요

연습 앱에서 F12 → Elements(요소) 내부 클릭 → Ctrl+F → #관리자설정 검색 → data-password의 따옴표 안 값을 확인합니다. F12를 닫고 그 값을 연습용 교사 로그인에 입력합니다. 자기 앱에는 이 검색어가 없을 수 있으므로 AI에게 실제 파일과 확인 위치를 받습니다.

### 구현할 때 적용할 조건

- 기존 인증 수단이 있으면 그것을 유지하고 서버가 로그인 상태와 교사 권한을 확인하도록 최소 수정안을 제시해 줘.

- 비밀번호나 역할을 브라우저에서 바꾸는 것만으로 보호 자료를 받을 수 없게 해 줘.

- 인증 서버가 없다면 보호 자료를 공개 파일로 두지 않는 방안과 필요한 서버 구성을 비교하고 내 선택을 기다려 줘.

- 학생용 기능과 현재 디자인은 유지해 줘. F12 차단이나 글자 난독화를 해결책으로 제시하지 마.

### 1 현재 상태부터 확인하기

사용할 때: 프로젝트를 연 뒤 처음 보냅니다. 파일을 고치기 전 단계입니다.

```text
활동: F12로 교사용 비밀번호 찾기
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 연습 앱 주소, 자기 앱의 교사 접속 방식, 가상 계정
현재 상황: [입력]
사용할 가상 자료: [입력]

이 활동에 해당하는지부터 확인해 줘. 아직 파일이나 설정은 수정하지 마.
1. 연습 앱에서 찾은 비밀번호가 왜 학생 브라우저에도 전달되는지 HTML의 숨김과 서버 권한 검사를 구분해 설명해 줘.
2. 내 프로젝트에서 비밀번호·교사 코드·관리자 여부를 브라우저 코드나 저장값과 비교하는 부분을 찾아 줘.
3. 숨겨진 입력, HTML 속성, 내려받는 JavaScript, 브라우저 저장소에 보호해야 할 값이 있는지 비밀값을 출력하지 않고 위치만 알려 줘.
4. 화면을 열 수 있는지뿐 아니라 교사용 데이터 요청이 서버에서 차단되는지 확인할 시험 계획을 세워 줘.

결과는 표로 정리해 줘. 표에는 확인 항목, 현재 동작, 근거가 있는 파일이나 설정 위치, 발견한 문제와 추가로 확인할 내용을 적어 줘. 코드에서 확인한 사실과 추정은 구분해 줘. 내가 직접 확인할 메뉴·버튼·파일 이름도 알려 줘. 파일을 읽지 못했다면 그 사실을 표시해 줘.
실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
참고할 확인 위치: 연습 앱에서 F12 → Elements(요소) 내부 클릭 → Ctrl+F → #관리자설정 검색 → data-password의 따옴표 안 값을 확인합니다. F12를 닫고 그 값을 연습용 교사 로그인에 입력합니다. 자기 앱에는 이 검색어가 없을 수 있으므로 AI에게 실제 파일과 확인 위치를 받습니다.
```

다음 행동: 현재 구조와 해당 여부를 확인합니다. 모르는 정보는 먼저 확인하고, 수정이 필요하면 2번으로 진행합니다.

### 2 수정 방법과 범위 정하기

사용할 때: 1번 답변에서 실제로 고칠 항목을 골랐을 때 보냅니다.

```text
활동: F12로 교사용 비밀번호 찾기
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 연습 앱 주소, 자기 앱의 교사 접속 방식, 가상 계정
현재 상황: [입력]
사용할 가상 자료: [입력]
앞에서 확인한 문제와 근거: [1번 결과 중 해당 부분을 붙이기]
이번에 고칠 항목: [입력]

구현 전에 다음 조건으로 수정 계획을 만들어 줘.
1. 기존 인증 수단이 있으면 그것을 유지하고 서버가 로그인 상태와 교사 권한을 확인하도록 최소 수정안을 제시해 줘.
2. 비밀번호나 역할을 브라우저에서 바꾸는 것만으로 보호 자료를 받을 수 없게 해 줘.
3. 인증 서버가 없다면 보호 자료를 공개 파일로 두지 않는 방안과 필요한 서버 구성을 비교하고 내 선택을 기다려 줘.
4. 학생용 기능과 현재 디자인은 유지해 줘. F12 차단이나 글자 난독화를 해결책으로 제시하지 마.

기존 기능을 유지하면서 문제를 고칠 방법부터 제안해 줘. 방법이 여러 가지라면 필요한 서비스와 비용, 사용 방법이 달라지는 부분, 이전 상태로 되돌릴 방법을 비교해 줘. 반드시 고쳐야 할 부분과 선택해서 개선할 부분을 구분해 줘.
변경할 파일, 학생 또는 교사 화면에서 달라질 부분, 필요한 관리 설정, 시험할 가상 입력을 순서대로 적어 줘. 서버가 없는 앱이라면 지금 할 수 있는 것과 서버가 필요한 것을 분리해 줘.
아직 코드를 수정하거나 서비스를 만들지 마. 내가 결정해야 할 사항이 있으면 선택지와 차이를 설명하고 물어봐 줘.
```

다음 행동: 수정할 내용과 비용, 정보 수집·전송·보관 방식이 달라지는지 확인한 뒤 진행할 방법을 정합니다. 학교가 판단해야 하는 내용은 먼저 확인합니다.

### 3 선택한 범위 구현하기

사용할 때: 수정 계획을 검토한 뒤 승인할 범위를 직접 적고 보냅니다.

```text
활동: F12로 교사용 비밀번호 찾기
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 연습 앱 주소, 자기 앱의 교사 접속 방식, 가상 계정
현재 상황: [입력]
사용할 가상 자료: [입력]
승인한 수정안: [선택한 방법과 항목을 정확히 입력]
수정할 파일 또는 기능 범위: [입력]
이번에 제외할 것: [입력]

위에 승인한 범위만 구현해 줘. 시작 전에 현재 변경 파일을 확인해 다른 작업을 보존해 줘.
1. 기존 인증 수단이 있으면 그것을 유지하고 서버가 로그인 상태와 교사 권한을 확인하도록 최소 수정안을 제시해 줘.
2. 비밀번호나 역할을 브라우저에서 바꾸는 것만으로 보호 자료를 받을 수 없게 해 줘.
3. 인증 서버가 없다면 보호 자료를 공개 파일로 두지 않는 방안과 필요한 서버 구성을 비교하고 내 선택을 기다려 줘.
4. 학생용 기능과 현재 디자인은 유지해 줘. F12 차단이나 글자 난독화를 해결책으로 제시하지 마.

한 부분씩 수정하고 실행 결과를 확인해 줘. 기존 디자인과 정상 기능은 유지해 줘. 새 서비스 생성·운영 자료 삭제·유료 호출·커밋·푸시·배포는 이 요청에 구체적으로 승인한 경우에만 실행해 줘. 요청하지 않은 변경이 필요하면 진행 전에 이유를 설명해 줘.
수정 후 바꾼 파일과 이유, 실행한 검사, 아직 하지 못한 시험, 내가 누를 버튼 순서를 적어 줘. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

다음 행동: 빌드나 실행 오류가 없는지 확인한 뒤 4번으로 진행합니다. 허용해야 할 동작은 정상적으로 되고, 차단해야 할 동작은 막히는지 함께 시험합니다.

### 4 수정 결과 직접 확인하기

사용할 때: 구현이 끝났거나 기존 기능이 안전하게 동작하는지 검증할 때 보냅니다.

```text
활동: F12로 교사용 비밀번호 찾기
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 연습 앱 주소, 자기 앱의 교사 접속 방식, 가상 계정
현재 상황: [입력]
사용할 가상 자료: [입력]
이번 수정 내용: [입력 또는 기존 기능 검증]
시험할 버전과 주소: [입력]

다음 조건을 가상 자료로 다시 시험해 줘.
1. 로그아웃한 상태와 학생·담당 교사로 로그인한 상태에서 같은 보호 자료를 요청해, 각각 접근이 허용되는지 비교해 줘.
2. 브라우저의 역할 표시를 바꾸어도 서버가 자료를 주지 않는지 가상 환경에서 확인해 줘.
3. 오류 안내 뒤에 숨겨진 응답 본문에도 보호 자료가 없는지 확인해 줘.
4. 브라우저 파일에서 비밀번호를 지운 것과 노출된 기존 비밀번호를 변경하는 일을 구분해 보고해 줘.

내가 직접 따라 할 수 있도록 준비 계정과 상태 → 클릭 또는 입력 → 확인할 실제 탭·요청·필드 → 기대 결과를 항목마다 적어 줘.
확인할 위치: 연습 앱에서 F12 → Elements(요소) 내부 클릭 → Ctrl+F → #관리자설정 검색 → data-password의 따옴표 안 값을 확인합니다. F12를 닫고 그 값을 연습용 교사 로그인에 입력합니다. 자기 앱에는 이 검색어가 없을 수 있으므로 AI에게 실제 파일과 확인 위치를 받습니다.
자기 앱에서 이름이 다르면 코드와 실제 요청에서 맞는 이름을 찾아 줘. 실제로 존재하는지 확인하지 않은 요청명을 만들어 내지 마.
허용해야 할 동작과 차단해야 할 동작을 함께 시험해 줘. 항목마다 실행 여부, 실제 결과, 확인한 화면이나 기록을 적고, 시험하지 못했다면 이유를 설명해 줘. 응답 코드와 실제로 받은 자료를 함께 확인하고, 저장 기능이 있다면 저장된 결과도 확인해 줘.
이 활동을 완료해도 앱 전체의 안전이 보장된다고 표현하지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

다음 행동: 기대 결과와 실제 결과가 같으면 활동 기록을 정리합니다. 다르면 “오류 해결” 프롬프트를 사용하고 같은 조건으로 재시험합니다.

### 검색 결과가 없을 때

사용할 때: 기본 순서로 진행하다가 이 상황에 해당하면 사용합니다.

```text
활동: F12로 교사용 비밀번호 찾기
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 연습 앱 주소, 자기 앱의 교사 접속 방식, 가상 계정
현재 상황: [입력]
사용할 가상 자료: [입력]
현재 겪는 상황: 검색 결과가 없을 때
이미 한 행동과 나온 결과: [입력]

현재 연습 앱 탭인지 확인하고 Elements 안에서 검색했는지 확인해 줘. 학교 기기 제한이나 다른 화면일 가능성을 구분하고 비밀번호를 임의로 만들어 답하지 마.
먼저 관련 코드·화면·설정에서 현재 상태를 확인하고 이 상황이 생긴 이유를 근거와 함께 설명해 줘. 현재 환경에서 확인할 수 없는 것은 따로 표시해 줘.
이 활동에서 유지할 조건:
1. 기존 인증 수단이 있으면 그것을 유지하고 서버가 로그인 상태와 교사 권한을 확인하도록 최소 수정안을 제시해 줘.
2. 비밀번호나 역할을 브라우저에서 바꾸는 것만으로 보호 자료를 받을 수 없게 해 줘.

진행 순서를 “지금 확인할 것 → 선택 가능한 방법 → 내가 승인할 변경 → 실행 후 다시 확인할 결과”로 정리해 줘. 앱에 필요 없는 기능을 추가하거나 검사를 끄는 방식으로 해결하지 마.
재시험에서는 다음 조건을 포함해 줘:
1. 로그아웃한 상태와 학생·담당 교사로 로그인한 상태에서 같은 보호 자료를 요청해, 각각 접근이 허용되는지 비교해 줘.

수정이 필요하면 먼저 범위를 제안하고 내 확인 전 운영 설정을 바꾸지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

### 반코드가 공개돼도 되는 입장 코드일 때

사용할 때: 기본 순서로 진행하다가 이 상황에 해당하면 사용합니다.

```text
활동: F12로 교사용 비밀번호 찾기
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 연습 앱 주소, 자기 앱의 교사 접속 방식, 가상 계정
현재 상황: [입력]
사용할 가상 자료: [입력]
현재 겪는 상황: 반코드가 공개돼도 되는 입장 코드일 때
이미 한 행동과 나온 결과: [입력]

입장 코드의 용도와 교사 비밀번호를 구분해 줘. 코드만으로 접근할 수 있는 자료를 확인하고 공개 가능한 범위와 추가 권한이 필요한 범위를 제안해 줘.
먼저 관련 코드·화면·설정에서 현재 상태를 확인하고 이 상황이 생긴 이유를 근거와 함께 설명해 줘. 현재 환경에서 확인할 수 없는 것은 따로 표시해 줘.
이 활동에서 유지할 조건:
1. 기존 인증 수단이 있으면 그것을 유지하고 서버가 로그인 상태와 교사 권한을 확인하도록 최소 수정안을 제시해 줘.
2. 비밀번호나 역할을 브라우저에서 바꾸는 것만으로 보호 자료를 받을 수 없게 해 줘.
3. 인증 서버가 없다면 보호 자료를 공개 파일로 두지 않는 방안과 필요한 서버 구성을 비교하고 내 선택을 기다려 줘.

진행 순서를 “지금 확인할 것 → 선택 가능한 방법 → 내가 승인할 변경 → 실행 후 다시 확인할 결과”로 정리해 줘. 앱에 필요 없는 기능을 추가하거나 검사를 끄는 방식으로 해결하지 마.
재시험에서는 다음 조건을 포함해 줘:
1. 로그아웃한 상태와 학생·담당 교사로 로그인한 상태에서 같은 보호 자료를 요청해, 각각 접근이 허용되는지 비교해 줘.
2. 브라우저의 역할 표시를 바꾸어도 서버가 자료를 주지 않는지 가상 환경에서 확인해 줘.
수정이 필요하면 먼저 범위를 제안하고 내 확인 전 운영 설정을 바꾸지 마. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

### 안내된 화면이나 요청을 찾지 못할 때

사용할 때: F12에 설명한 파일·요청이 없거나 확인할 곳을 모르겠을 때 보냅니다.

```text
활동: F12로 교사용 비밀번호 찾기
앱 이름과 프로젝트: [입력]
이번 시험 주소: [입력]
준비 정보: 연습 앱 주소, 자기 앱의 교사 접속 방식, 가상 계정
현재 상황: [입력]
사용할 가상 자료: [입력]
내가 보고 있는 주소와 창: [입력]
누른 버튼 또는 실행한 동작: [입력]
열어 둔 개발자 도구 탭과 필터: [입력 또는 모름]
찾으려는 정보: [입력]
현재 화면 또는 가린 오류 내용: [붙이기]

참고 안내: 연습 앱에서 F12 → Elements(요소) 내부 클릭 → Ctrl+F → #관리자설정 검색 → data-password의 따옴표 안 값을 확인합니다. F12를 닫고 그 값을 연습용 교사 로그인에 입력합니다. 자기 앱에는 이 검색어가 없을 수 있으므로 AI에게 실제 파일과 확인 위치를 받습니다.
이 안내가 체험 앱의 가상 자료인지 내 앱의 실제 동작인지 먼저 구분해 줘. 프로젝트에서 이 동작이 어떤 요청·파일·저장소로 연결되는지 찾아 줘.
Network라면 동작 전에 열기, 기록 켜기, 목록 지우기, 필터 확인, 같은 동작 다시 하기, 새 요청 선택, Headers·Payload·Response 중 볼 위치를 실제 이름으로 알려 줘. 정적 파일이면 All 필터도 확인해 줘. 새 창을 열었다면 그 창에서 F12를 열어야 하는지 설명해 줘.
브라우저 검사에서 막아 요청이 없거나 아직 동작을 실행하지 않은 경우도 구분해 줘. 서버에만 있는 정보는 F12에서 찾으라고 하지 말고 코드·관리 화면·시험 환경에서 확인할 방법을 제시해 줘.
확인할 자료가 실제로 없으면 없다고 말하고 필요한 시험 준비를 설명해 줘. 캡처 요청에는 가려야 할 정보도 알려 줘. 실제 학생 정보·비밀키·인증 토큰은 출력하지 말고 필요한 값은 가려 줘. 내 앱 또는 허락받은 시험 환경만 대상으로 해 줘.
```

다음 행동: 정확한 위치를 찾은 뒤 해당 활동의 4번 프롬프트로 결과를 확인합니다. 없다는 사실 자체가 기대 결과인지 먼저 판단합니다.

### 예상과 다른 결과가 나올 때

사용할 때: 실행 오류, 정상 기능 실패, 예상한 차단이 되지 않는 경우에 보냅니다.

```text

실제로 나온 결과: [입력]
오류 문구: [비밀값을 가리고 붙이기]
직전에 변경한 파일 또는 설정: [입력 또는 모름]

원인을 추측해서 여러 곳을 한꺼번에 바꾸지 말고, 재현 조건과 현재 코드를 비교해 줘. 요청이 만들어지는지, 서버에 도착하는지, 검사와 반환·저장이 어디서 달라지는지 관련 단계만 확인해 줘.
특히 다음 점검 기준을 다시 봐 줘:
1. 연습 앱에서 찾은 비밀번호가 왜 학생 브라우저에도 전달되는지 HTML의 숨김과 서버 권한 검사를 구분해 설명해 줘.
2. 내 프로젝트에서 비밀번호·교사 코드·관리자 여부를 브라우저 코드나 저장값과 비교하는 부분을 찾아 줘.

가능한 원인마다 그렇게 판단한 이유와 먼저 확인할 방법을 알려 줘. 운영 자료를 삭제하거나 권한·입력 검사를 전체 해제하는 방식은 사용하지 마. 수정이 필요하면 바꿀 내용을 먼저 제안하고 내가 승인한 뒤 적용해 줘.
수정 후 같은 실패 조건과 다음 정상 조건을 모두 재시험해 줘:
1. 로그아웃한 상태와 학생·담당 교사로 로그인한 상태에서 같은 보호 자료를 요청해, 각각 접근이 허용되는지 비교해 줘.
2. 브라우저의 역할 표시를 바꾸어도 서버가 자료를 주지 않는지 가상 환경에서 확인해 줘.
3. 오류 안내 뒤에 숨겨진 응답 본문에도 보호 자료가 없는지 확인해 줘.
4. 브라우저 파일에서 비밀번호를 지운 것과 노출된 기존 비밀번호를 변경하는 일을 구분해 보고해 줘.
완료 보고에는 실제 실행한 결과와 실행하지 못한 이유를 구분해 줘.
```
