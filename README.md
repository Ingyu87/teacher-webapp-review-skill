# 교사 웹앱 배포 전 점검 스킬

교사가 만든 웹앱을 AI 코딩 도구와 함께 점검하기 위한 스킬입니다. 백인규의 활동별 상세 프롬프트 부록을 바탕으로 만들었습니다. 비개발자 교사도 결과를 이해하고 직접 확인할 수 있도록 설명합니다.

## 무엇을 하나요

자기 프로젝트에서 로그인·권한·API 키·정보 전송 등 해당하는 항목을 찾아 점검합니다. 필요하면 학생 수업 운영, 이용약관과 개인정보처리방침, 학교 제출 체크리스트, 포털 운영까지 참고할 수 있습니다. **37개 활동을 전부 수행할 필요는 없습니다.**

기본은 점검과 결과 설명입니다. 코드 수정이나 배포를 요청하지 않았다면 자동으로 수정·커밋·푸시·배포하지 않습니다. 스킬 자체에 외부 API나 데이터베이스는 필요하지 않습니다. 사용하는 AI 도구의 요금과 권한은 별개입니다.

## 점검 결과는 어떻게 설명하나요

발견 사항은 확인 사실·적용 기준·구체적인 차이·영향·기존 대책을 대조한 뒤 **필수 조치·확인 먼저·권장 개선**으로 구분합니다. 단순한 안내 보강이나 특정 삭제 기능의 부재만으로 필수라고 판단하지 않습니다. 필요한 결과와 선택할 구현 방법, 조치 필요성과 조치 시점을 구분합니다.

다시 “꼭 해야 하나?”라고 물으면 기존 근거를 재검토합니다. 판단을 바꿀 때는 이전·새 판단과 변경 이유를 설명하도록 했습니다. 사용자 반응에 맞춰 등급을 낮추거나 근거 없는 첫 판단을 고집하지 않도록 하는 지침입니다.

예를 들어 삭제 코드가 없더라도 별도 자동 정리가 있을 수 있으므로 먼저 실제 설정을 확인하도록 안내합니다. 확인 결과 필요한 정리가 이미 이루어진다면 중복 수정을 요구하지 않습니다. 이는 보고 방식의 예시이며 특정 앱을 검사한 결과가 아닙니다.

## 설치와 사용

설치할 스킬 폴더는 [`skills/teacher-webapp-review`](skills/teacher-webapp-review)입니다. `SKILL.md`뿐 아니라 `agents`와 `references`를 포함한 폴더 전체를 설치하세요. 저장소 전체를 사용자 웹앱에 복사할 필요는 없습니다.

Codex에서 다음과 같이 요청할 수 있습니다.

```text
https://github.com/Ingyu87/teacher-webapp-review-skill 저장소의
skills/teacher-webapp-review 폴더를 내 사용자 스킬로 설치해 줘.
```

스킬이 목록에 표시되는지 확인한 뒤 **자기가 만든 웹앱 프로젝트를 열고** 요청합니다. 다른 AI 코딩 도구에서는 그 도구의 스킬 설치 방식에 맞춰 같은 폴더를 사용하세요.

### 수정 없이 점검

```text
$teacher-webapp-review
내가 만든 웹앱을 점검해 줘. 학생 수업용이고 AI 질문 기능이 있어.
내 앱에 해당하는 활동만 골라서 근거와 확인 방법을 설명해 줘.
코드나 설정은 아직 바꾸지 마.
```

### 한 부분만 점검

```text
$teacher-webapp-review
API 키 노출과 다른 학생 기록에 접근할 수 있는지만 점검해 줘.
F12에서 내가 확인할 탭, 요청 이름과 항목을 실제 앱 기준으로 알려 줘.
```

### 점검 결과를 보고 수정 요청

```text
$teacher-webapp-review
앞서 확인한 문제 중 학생별 기록 접근 권한만 수정해 줘.
기존 디자인과 다른 기능은 유지해 줘.
가상 학생 A와 B로 정상 접근과 차단 동작을 재시험해 줘.
운영 배포는 하지 마.
```

### 학교 제출 자료 준비

```text
$teacher-webapp-review
내 앱의 실제 기능과 정보 처리 방식에 맞춰
이용약관·개인정보처리방침 초안과 공급자 체크리스트를 준비해 줘.
학교 양식은 내가 제공할게. 확인하지 못한 사실은 질문으로 구분해 줘.
```

## 자료 구성

- [스킬 실행 지침](skills/teacher-webapp-review/SKILL.md): 요청 범위와 점검 방법
- [활동별 목차](skills/teacher-webapp-review/references/index.md): 37개 활동과 적용 상황
- [공통 안내](skills/teacher-webapp-review/references/common.md): F12 사용법과 기본 용어
- [조치 필요성 판단과 결과 작성](skills/teacher-webapp-review/references/reporting.md): 필수·확인 먼저·권장 구분과 구체적인 후속 조치
- 활동별 참고 파일: 기본 진행, 상황별 분기, 확인 위치, 오류 해결, 재시험 프롬프트

공통 시작문을 포함해 원자료의 337개 프롬프트를 보존했습니다. AI는 목차에서 필요한 활동만 읽습니다. 참고 파일 안의 구현·배포 예시는 사용자가 실행을 승인한 것으로 취급하지 않습니다.

## 확인할 수 있는 범위

프로젝트 접근 권한이 있어야 코드를 점검할 수 있습니다. 서버 내부 저장, 운영 콘솔의 설정, 실제 과금, 학교의 적용 판단은 추가 자료나 운영자의 확인이 필요할 수 있습니다. 코드 검토만으로 앱 전체의 안전이나 학교 심의 통과를 보장하지 않습니다.

참고 링크에는 선택해서 사용할 수 있는 [연습용 보안 체험 앱](https://webapp-security-lab.vercel.app/)과 공개 사례가 있습니다. 연습용 파일·요청 이름을 자기 앱의 이름으로 착각하지 않도록 안내합니다. 타인이 운영하는 공개 사례에 공격성 시험을 해서는 안 됩니다.

법령·학교 지침·서비스 설정은 실제 검토 시 최신 공식 자료로 다시 확인하도록 설계했습니다. 작성 당시의 링크와 예시가 현재 기준을 대신하지 않습니다.

## 검증과 자료 갱신

`node scripts/validate.mjs`로 참고 파일과 링크의 연결, 활동 수와 프롬프트 수를 검사할 수 있습니다. 이는 실제 웹앱의 보안 검사를 실행하지 않습니다. 실제 사용자 프로젝트에서의 점검 성능을 인증하는 시험도 아닙니다.

[판단 검토 사례](tests/review-cases.md)는 필수 판정, 기존 대책, 안내의 구체성, 재질문에 대한 답변을 검토하기 위한 가상 자료입니다. 파일 구조 검사와 구분해 사용하며, 다른 모델이나 도구에서 실제로 실행하지 않은 사례를 자동 시험 통과로 보고하지 않습니다.

원자료 MD를 가지고 있는 작성자는 다음 명령으로 활동 파일을 다시 분리할 수 있습니다. 원자료는 수정하지 않습니다. 기존 활동 파일은 갱신되므로 변경 내용을 검토한 뒤 커밋하세요.

```text
node scripts/package_from_appendix.mjs 원자료.md
node scripts/validate.mjs
```
